NapCat implements the [OneBot 11](https://11.onebot.dev/) protocol and extends it with dozens of NapCat-specific actions. Every action — whether a standard OB11 call or a NapCat extension — shares the same request/response shape and can be invoked over **HTTP POST** or **WebSocket**. This page explains how to call actions, how to authenticate, and where to find documentation for each action group.

## Transport methods

NapCat supports five network adapter types (HTTP server, HTTP SSE server, HTTP client, WebSocket server, WebSocket client). Actions are invoked through the HTTP server or WebSocket server adapters.

### HTTP POST

Send a `POST` request to `http://{host}:{port}/{action_name}` with a JSON body containing the action parameters. The default host is `127.0.0.1` and the default port is `3000` (set in your HTTP server adapter config).

```bash
curl -X POST http://127.0.0.1:3000/send_group_msg \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your_token_here" \
  -d '{
    "group_id": 123456789,
    "message": [{ "type": "text", "data": { "text": "Hello from NapCat!" } }]
  }'
```

Action names also accept the `_async` and `_rate_limited` suffixes (e.g. `send_group_msg_async`), which resolve to the same handler — these are provided for compatibility with go-cqhttp clients.

### WebSocket

Connect to `ws://{host}:{port}` and send a UTF-8 text frame containing a JSON object. The `action` field names the action, `params` carries the payload, and `echo` is an optional correlation ID that NapCat echoes back unchanged in the response.

```json
{
  "action": "send_group_msg",
  "params": {
    "group_id": 123456789,
    "message": [{ "type": "text", "data": { "text": "Hello!" } }]
  },
  "echo": "abc123"
}
```

<Tip>
  The WebSocket adapter default port is `3001`. Adjust `host` and `port` in your `websocketServers` config block to match your deployment.
</Tip>

## Authentication

All adapter types support a shared `token` field in the adapter config. When a token is set, every request must supply it.

| Transport | Method |
|-----------|--------|
| HTTP | `Authorization: Bearer <token>` request header, **or** `?access_token=<token>` query parameter |
| WebSocket (connection) | `?access_token=<token>` query parameter on the WebSocket URL, **or** `Authorization: Bearer <token>` header on the upgrade request |

<Warning>
  Leaving the token empty disables authentication entirely. Always set a strong token on any adapter that is accessible from outside `localhost`.
</Warning>

## Action categories

NapCat registers over 200 named actions. They are grouped below by function. The `_async` and `_rate_limited` variants of each name map to the same handler and are omitted for brevity.
