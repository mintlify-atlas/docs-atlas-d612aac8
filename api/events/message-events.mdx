title: "Receive and handle message events from NapCat"

NapCat pushes a JSON payload to your bot every time a message is received. These payloads follow the OneBot 11 `message` event shape, extended by NapCat's `message_sent` post type for messages your bot sends itself. Each event is a complete self-contained object — you never need to make a follow-up API call to read the full message content.

## Base event shape

All NapCat events share a three-field base defined by `OneBotEvent`:

<ResponseField name="time" type="number" required>
  Unix timestamp (seconds) of when the event was generated by NapCat.
</ResponseField>

<ResponseField name="self_id" type="number" required>
  The QQ UIN of the bot account that received this event.
</ResponseField>

<ResponseField name="post_type" type="string" required>
  Discriminator that identifies the broad event category. See the `EventType` enum:

  | Value | Meaning |
  |-------|---------|
  | `message` | An incoming message received by the bot |
  | `message_sent` | A message sent by the bot itself |
  | `notice` | A notice event (group change, friend action, etc.) |
  | `request` | A friend-add or group-join request |
  | `meta_event` | Heartbeat or lifecycle meta event |
</ResponseField>

## Message event fields

When `post_type` is `'message'` or `'message_sent'`, the payload extends the base with the following fields from `OB11BaseMessageEvent`:

<ResponseField name="message_type" type="'private' | 'group'" required>
  Whether this is a private (one-on-one) message or a group message.
</ResponseField>

<ResponseField name="sub_type" type="string" required>
  A secondary discriminator whose valid values depend on `message_type`:

  | `message_type` | Valid `sub_type` values |
  |----------------|------------------------|
  | `private` | `'friend'`, `'group'`, `'other'`, `'normal'` |
  | `group` | `'normal'`, `'anonymous'`, `'notice'` |

  For private messages, `'friend'` means a direct friend conversation; `'group'` means a private message that originated from inside a group (e.g. a group temp message).
</ResponseField>

<ResponseField name="message_id" type="number" required>
  NapCat's internal ID for this message. Use this with `get_msg`, `delete_msg`, `set_msg_emoji_like`, and similar actions.
</ResponseField>

<ResponseField name="user_id" type="number" required>
  QQ UIN of the user who sent the message.
</ResponseField>

<ResponseField name="message" type="array | string" required>
  The parsed message content. By default this is an **array of message segment objects** (one element per segment type such as text, image, at, face, etc.). When the `messagePostFormat` adapter option is set to `'string'`, NapCat emits the raw CQ-code string here instead.
</ResponseField>

<ResponseField name="raw_message" type="string" required>
  The CQ-code string representation of the message, regardless of the `messagePostFormat` setting. Useful when you need the raw format unconditionally, or for logging.
</ResponseField>

<ResponseField name="font" type="number" required>
  Legacy font identifier inherited from the OneBot 11 spec. Always `0` in NapCat.
</ResponseField>

<ResponseField name="sender" type="object" required>
  Information about the message sender.
  <Expandable title="sender fields">
    <ResponseField name="user_id" type="number">QQ UIN of the sender.</ResponseField>
    <ResponseField name="nickname" type="string">The sender's global QQ nickname.</ResponseField>
    <ResponseField name="sex" type="string">Gender string from the QQ profile (e.g. `'male'`, `'female'`, `'unknown'`).</ResponseField>
    <ResponseField name="age" type="number">Age from the QQ profile.</ResponseField>
    <ResponseField name="card" type="string">
      The sender's group card (nickname inside the group). Present on group messages only; empty string if no card is set.
    </ResponseField>
    <ResponseField name="role" type="'owner' | 'admin' | 'member'">
      The sender's role in the group. Present on group messages only.
    </ResponseField>
    <ResponseField name="title" type="string">
      The sender's exclusive title in the group, if set. Present on group messages only.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="group_id" type="number">
  ID of the group the message was sent in. Present on group messages only (`message_type: 'group'`).
</ResponseField>

<ResponseField name="anonymous" type="object | null">
  If the message was sent anonymously in a group, this object contains the anonymous identity (`id`, `name`, `flag`). `null` for all non-anonymous messages.
</ResponseField>

## Message segment shape

When `message` is an array (the default), each element follows this structure:

```json
{
  "type": "<segment_type>",
  "data": { /* segment-specific key/value pairs */ }
}
```

Common segment types include `text`, `image`, `at`, `face`, `record`, `video`, `reply`, `forward`, `json`, `xml`, and many NapCat extensions. See the [Message Types](/api/messages/types) reference for the full list and per-type field documentation.

  "message_type": "private",
  "sub_type": "friend",

  "user_id": 10001,
  "message": [{ "type": "text", "data": { "text": "Hello!" } }],
  "raw_message": "Hello!",
  "font": 0,
  "sender": {
    "user_id": 10001,
    "nickname": "Alice",
    "sex": "female",
    "age": 25
  },

  "self_id": 99999
}
```

  "message_type": "group",
  "sub_type": "normal",

}
```

}

</CodeGroup>

## Self-sent messages

NapCat can optionally emit events for messages the bot sends itself. When `post_type` is `'message_sent'`, the event structure is identical to a regular message event — the only difference is the `post_type` value.

<Note>
  Self-sent message events are controlled by the `reportSelfMessage` option in your adapter configuration. Set it to `true` to enable these events. They are disabled by default to avoid bots reacting to their own output.
</Note>

## Delivery mechanisms

How NapCat delivers events to your bot depends on which adapter type you have configured.

<Tabs>
  <Tab title="Webhook (HTTP client)">
    When an **HTTP client** adapter is configured, NapCat makes a `POST` request to your webhook URL for each event. Your server must return HTTP `200` within the configured timeout.

    ```json
    POST https://your-bot.example.com/napcat-webhook
    Content-Type: application/json

    { ...event payload... }
    ```

    <Tip>
      NapCat retries failed webhook deliveries based on the `retryInterval` setting in your HTTP client adapter config.
    </Tip>
  </Tab>
  <Tab title="WebSocket server">
    When a **WebSocket server** adapter is configured, NapCat pushes raw JSON text frames to every connected client. Connect to `ws://{host}:{port}` and parse each incoming frame as a JSON object. Check `post_type` to route the event.

    ```json
    {
      "post_type": "message",
      "message_type": "private",
      ...
    }
    ```
  </Tab>
  <Tab title="WebSocket client">
    When a **WebSocket client** adapter is configured, NapCat connects outward to your WebSocket server and pushes event frames the same way as the server mode — you receive JSON text frames on your end of the connection.
  </Tab>
</Tabs>

## Meta events

In addition to message events, NapCat emits two types of meta events (`post_type: 'meta_event'`):

| `meta_event_type` | When it fires | Key fields |
|-------------------|---------------|------------|
| `heartbeat` | Periodically, at the interval set by `heartInterval` in your adapter config | `status`, `interval` |
| `lifecycle` | On adapter connect or disconnect | `sub_type: 'connect'` or `'disconnect'` |

Use heartbeat events to monitor connection health and detect dropped WebSocket connections.
